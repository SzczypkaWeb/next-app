# next-app

## Stack
Next.js (App Router), React, Tailwind CSS v4. SSR marketing/listing pages
(e.g. `/uslugi/hydraulik/warszawa`) that hand off to `frontend-shell` (the
Module Federation app) for anything requiring auth or app state.

## Run / test
- `pnpm install` then `pnpm dev`.
- `pnpm test` — Vitest + @testing-library/react.
- `pnpm lint` — ESLint, zero warnings allowed.
- `pnpm typecheck` — `tsc --noEmit`.
- `pnpm build` — production build.

## Structure
- `app/` — App Router routes (file-based).
- `lib/` — shared helpers (data fetching, formatting) used by route components.
- `public/` — static assets.

## Conventions
- UI components come from `@szczypkaweb/shared-ui` — see that repo's CLAUDE.md
  for styling conventions before styling something from scratch here.
- SSR pages are the entry point for anonymous/SEO traffic; anything needing
  login or app state (posting a request, messaging) redirects to
  `frontend-shell`, passing context via query params (category, location)
  rather than duplicating that flow here.
- Conventional commits, everything in English.

## Never do
- Never duplicate a component that already exists in `@szczypkaweb/shared-ui`.
- Never build authenticated/app-state flows here — that's `frontend-shell`'s
  job; this app stays SSR-public.
- Never hand-edit the `<!-- BEGIN:nextjs-agent-rules -->` block in
  `AGENTS.md` — it's regenerated by `next dev`; commit it as-is if it
  reappears in a diff.
- Never merge with a red `pnpm lint`/`pnpm typecheck`/`pnpm test`.
